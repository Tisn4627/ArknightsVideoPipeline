# 快速使用

## 项目简介

ArknightsVideoRecognition 是把 Maa（明日方舟助手）的"视频转标准作业 JSON"功能用 Python 重写的项目。它接受一段明日方舟战斗录像视频作为输入，识别其中的编队、关卡与战斗操作（部署 / 技能 / 撤退等），输出符合 Maa copilot schema 的作业 JSON，可直接导入 Maa 用于自动战斗（copilot 模式）。地图识别采用社区标准 Arknights-Tile-Pos 形式（单文件 `levels.json` + 3D 投影矩阵），OCR 使用 RapidOCR 并支持双模型源切换。

## 环境要求

- Python >= 3.9
- 依赖包：numpy、opencv-python、onnxruntime、rapidocr-onnxruntime、pillow（安装项目时自动拉取）
- 资源已内置在 `/workspace/resource/`（约 214M，全部纳入版本控制），开箱即用
- 如需更新资源，本地需要预先存在以下上游仓库（用于资源同步，非运行依赖）：
  - `/ArknightsResources`：`https://github.com/yuanyan3060/ArknightsGameResource`（地图数据、干员头像）
  - `/Maa`：`https://github.com/MaaAssistantArknights/MaaAssistantArknights`（ONNX 模型、OCR 模型、模板、战斗/OCR 配置）

## 安装

在项目根目录下开发安装：

```bash
cd /workspace
pip install -e .
```

也可以用普通安装：

```bash
pip install .
```

安装后即可使用命令行入口 `arknights-video-recognition`，或继续用 `python -m ArknightsVideoRecognition`。

## 资源准备

`/workspace/resource/` 已内置全部必需资源（约 214M），包含地图数据、干员头像、ONNX 模型、OCR 模型、模板图片、战斗/OCR 配置等，安装后无需额外下载即可运行。

若资源缺失或损坏，运行更新脚本从本地上游仓库同步：

```bash
python scripts/update_resources.py
```

脚本默认从 `/ArknightsResources` 和 `/Maa` 读取并复制到 `/workspace/resource/`。资源目录也可通过环境变量 `AVR_RESOURCE_DIR` 覆盖。

更新资源的方式：

- 更新地图数据：`python scripts/update_levels.py`（直接从 GitHub 下载，无需本地仓库）；或先 `git -C /ArknightsResources pull`，再运行 `python scripts/update_resources.py`。
- 更新干员职业表：`python scripts/update_character_table.py`（直接从 GitHub 下载 `character_table.json` 并提取 `char_roles.json`）。
- 更新 ONNX / OCR / 模板 / 干员数据：先 `git -C /Maa pull`，再运行 `python scripts/update_resources.py`。
- 更新干员头像：先 `git -C /ArknightsResources pull`，再运行 `python scripts/update_resources.py`。
- 重新生成 ROI 配置：`python scripts/update_resources.py --regen-roi`（从 Maa 的 `tasks.json` 重新提取视频识别相关任务）。

资源的详细来源、许可证与更新方式见 [资源来源.md](./资源来源.md)。

## 快速开始

把一段战斗录像视频转换为 Maa copilot 作业 JSON：

```bash
python -m ArknightsVideoRecognition /path/to/battle.mp4 -o /tmp/job.json
```

成功后会在标准输出打印实际写入的 JSON 文件路径（此处即 `/tmp/job.json`）。不指定 `-o` 时，作业会自动命名存到 `/workspace/cache/MaaAI_{stage}_{video_stem}_{timestamp}.json`。

一个更完整的示例（手动指定关卡、指定 OCR 模型源）：

```bash
python -m ArknightsVideoRecognition battle.mp4 --stage 2-10 --ocr maamodel -o out.json
```

也可使用安装后的入口命令：

```bash
arknights-video-recognition battle.mp4 --output out.json
```

## CLI 参数说明

```
python -m ArknightsVideoRecognition <video> [--ocr {maamodel,default}] [-o OUTPUT] [--stage STAGE] [--resolution WxH] [--with-video-time]
```

| 参数 | 是否必填 | 默认值 | 含义 | 示例 |
| --- | --- | --- | --- | --- |
| `video` | 是（位置参数） | — | 输入的战斗录像视频文件路径 | `battle.mp4` |
| `--ocr` | 否 | `maamodel` | OCR 模型源。`maamodel` 复用 Maa 的方舟 finetune 模型（方舟专用精度）；`default` 使用 RapidOCR pip 包自带模型 | `--ocr default` |
| `-o` / `--output` | 否 | 自动命名 | 输出 JSON 路径。不指定则存到 `/workspace/cache/MaaAI_{stage}_{video_stem}_{timestamp}.json` | `-o /tmp/job.json` |
| `--stage` | 否 | 自动 OCR 识别 | 手动指定关卡，支持 code / name / stageId 任一形式。OCR 识别失败或想跳过 OCR 时使用 | `--stage 2-10` |
| `--resolution` | 否 | `1280x720` | 视频归一化分辨率，形如 `WxH`。用于把视频帧坐标归一化到标准分辨率 | `--resolution 1920x1080` |
| `--with-video-time` | 否 | 关闭 | 在 actions 中输出 `video_time` 扩展字段（视频内绝对时间戳，秒）。默认关闭以输出纯 Maa 标准格式 | `--with-video-time` |

退出码约定：

- `0`：成功（标准输出打印输出文件路径）
- `1`：资源缺失 / 视频无法打开 / 其它异常
- `2`：关卡未识别（会打印候选关卡，并提示用 `--stage` 手动指定）

## 输出说明

### 文件位置

- 显式指定 `-o`：写入指定路径。
- 未指定 `-o`：写入 `/workspace/cache/MaaAI_{stage}_{video_stem}_{timestamp}.json`，其中 `{stage}` 为关卡 stageId，`{video_stem}` 为视频文件名（去扩展名），`{timestamp}` 为 `YYYYMMDD_HHMMSS` 时间戳。

### JSON 字段含义

输出遵循 Maa copilot schema（协议文档见 `/Maa/docs/zh-cn/protocol/copilot-schema.md`）：

```json
{
  "minimum_required": "v4.0.0",
  "stage_name": "<stageId>",
  "opers": [{"name":"...","skill":0}],
  "groups": [],
  "actions": [
    {"type":"SpeedUp"},
    {"type":"Deploy","name":"...","location":[x,y],"direction":"Right"},
    {"type":"Skill","name":"...","location":[x,y]},
    {"type":"Retreat","name":"...","location":[x,y]},
    {"type":"SkillDaemon"}
  ],
  "doc": {"title":"MAA AI - <stage>","details":""}
}
```

字段说明：

- `minimum_required`：最低要求 Maa 版本号，固定 `v4.0.0`。
- `stage_name`：关卡标识，使用 stageId（如 `main_02-10`）。
- `opers`：编队干员列表，每项含 `name`（干员名）与 `skill`（技能序号，默认 0，对齐 Maa 原版输出）。
- `groups`：干员组，本项目输出为空数组。
- `actions`：操作序列。开头固定为 `SpeedUp`（二倍速），中间为识别到的 `Deploy` / `Skill` / `Retreat`，结尾固定为 `SkillDaemon`（摆完挂机）。
  - `type`：操作类型（Deploy / Skill / Retreat / SpeedUp / SkillDaemon 等）。
  - `name`：干员名（Deploy / Skill / Retreat 带）。
  - `location`：`[x, y]`，其中 **x = 列、y = 行**，对应 `levels.json` 的 `tiles[row][col]`。
  - `direction`：部署朝向（Right / Down / Left / Up / None），仅 Deploy 输出。
  - `video_time`：视频内绝对时间戳（秒），仅在使用 `--with-video-time` 时输出，非 Maa 标准扩展字段。
- `doc`：作业描述，`title` 形如 `MAA AI - <stageId>`。

> 注：本项目以视频中的时间点作为 actions 的时间点，与原 Maa 用 kills/costs 作为触发条件不同，因此输出中不含 `kills` / `costs` / `cost_changes` 字段。如需时间触发，可用 `--with-video-time` 输出 `video_time` 字段辅助定位。

### 导入 Maa 使用

将生成的 JSON 文件导入 Maa 客户端：在 Maa 的"自动战斗（copilot 模式）"中选择该作业文件，或把文件放到 Maa 的 `resource/copilot/` 目录下作为可复用作业，随后在战斗界面加载即可。也可以在 [https://map.ark-nights.com/areas](https://map.ark-nights.com/areas) 把"坐标展示"设为"MAA"来核验 `location` 坐标。

## OCR 模型源选择建议

| 模型源 | 适用场景 | 说明 |
| --- | --- | --- |
| `maamodel`（默认） | 推荐优先使用 | 复用 Maa 的方舟 finetune PaddleOCR onnx 模型，对方舟干员名 / 关卡名等专用文本识别精度更高。模型位于 `resource/ocr/maa/`。 |
| `default` | `maamodel` 资源缺失，或想用 RapidOCR 通用模型做对照 | 使用 RapidOCR pip 包自带的默认模型，无需额外模型文件，但对方舟专用文本识别精度略低。 |

通常保持默认 `maamodel` 即可。只有当 `resource/ocr/maa/` 缺失又无法及时同步时，才用 `--ocr default` 临时跑通流程。

## 常见问题（FAQ）

**Q：关卡识别失败怎么办？**

A：用 `--stage <code|name|stageId>` 手动指定关卡，例如 `--stage 2-10`。CLI 在识别失败时会打印候选关卡（最多 10 个）并提示该参数。识别失败常见于关卡名 ROI 不在标准位置或 OCR 把字符识错。

**Q：提示资源缺失怎么办？**

A：运行 `python scripts/update_resources.py` 从本地 `/Maa` 和 `/ArknightsResources` 仓库同步资源。脚本会列出缺失文件并复制。若本地没有这两个上游仓库，先按"环境要求"中的 URL `git clone` 到 `/Maa` 和 `/ArknightsResources`。地图数据也可用 `python scripts/update_levels.py` 直接从 GitHub 下载，干员职业表可用 `python scripts/update_character_table.py` 下载。

**Q：识别结果不准怎么办？**

A：检查视频分辨率与清晰度。用 `--resolution WxH` 指定视频真实分辨率（默认按 1280x720 归一化）。视频应清晰、无遮挡，关卡名和编队页出现在视频开头。模糊或低分辨率视频会影响 OCR 与干员检测精度。

**Q：识别不到任何干员怎么办？**

A：确认输入视频是标准的明日方舟战斗录像。本项目仅识别标准战斗流程（含编队页、关卡名、战斗过程）。非标准战斗录像（如剧情动画、模拟器录制裁剪过度）可能无法识别。

**Q：如何手动覆盖关卡名识别？**

A：使用 `--stage` 参数，支持 code（如 `2-10`）、name（关卡中文名）或 stageId（如 `main_02-10`）任一形式，直接查 `levels.json` 表，跳过 OCR。
