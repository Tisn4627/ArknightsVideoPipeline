# 资源来源

本文档逐项列出 `/workspace/resource/` 下每个资源的来源仓库、上游路径、许可证与更新方式，便于核对合规性与跟随上游更新。资源可通过 `scripts/update_resources.py` 从本地已克隆的上游仓库同步，或由 `scripts/update_levels.py` / `scripts/update_character_table.py` 直接从 GitHub 下载，均不修改上游仓库本身。

## 上游仓库

| 仓库 | 本地路径 | 远程地址 | 许可证 | 用途 |
| --- | --- | --- | --- | --- |
| ArknightsGameResource | `/ArknightsResources` | https://github.com/yuanyan3060/ArknightsGameResource | — | 标准地图数据（`levels.json`）、干员头像 |
| MaaAssistantArknights | `/Maa` | https://github.com/MaaAssistantArknights/MaaAssistantArknights | AGPL-3.0 | ONNX 模型、PaddleOCR 模型、战斗/OCR 配置、模板 |
| Kengxxiao/ArknightsGameData | （HTTP 下载，无需本地克隆） | https://github.com/Kengxxiao/ArknightsGameData | — | 干员职业表（`character_table.json`） |

> `levels.json` 也可由 `scripts/update_levels.py` 直接从 GitHub 下载，无需本地仓库。干员头像由 `scripts/update_resources.py` 从 `/ArknightsResources/avatar` 同步，需先 `git -C /ArknightsResources pull`。

### 4. 战斗/OCR 配置 JSON

| 项目 | 内容 |
| --- | --- |
| 本地路径 | `resource/data/battle_data.json`<br>`resource/data/ocr_config.json`<br>`resource/data/character_table.json`<br>`resource/data/char_roles.json` |
| 上游仓库 | MaaAssistantArknights（`battle_data.json` / `ocr_config.json`）<br>Kengxxiao/ArknightsGameData（`character_table.json`） |
| 上游路径 | `/Maa/resource/battle_data.json`<br>`/Maa/resource/ocr_config.json`<br>`https://raw.githubusercontent.com/Kengxxiao/ArknightsGameData/master/zh_CN/gamedata/excel/character_table.json` |
| 用途 | `battle_data.json`：干员元信息（name/name_en/name_tw/name_jp/name_kr 等别名），用于 `formation/analyzer` 校正 OCR 干员名；`ocr_config.json`：OCR 等价类替换规则（`equivalence_classes`）与 `ocrReplace` 正则规则，用于 `ocr/engine` 对识别文本做归一化（如繁简/易混字统一）；`character_table.json`：干员职业表（含 profession 字段），由 `scripts/update_character_table.py` 下载并提取为 `char_roles.json`；`char_roles.json`：`{干员名: 职业模板名}` 映射，用于 `battle/deployment` 部署栏匹配时的 role 过滤 |

| 加载方式 | `formation/analyzer._load_alias_index`、`ocr/engine._load_equivalence_rules` / `_load_replace_rules`、`battle/deployment.DeploymentAnalyzer.__init__` |
| 更新方式 | `battle_data.json` / `ocr_config.json`：先 `git -C /Maa pull`，再 `python scripts/update_resources.py`；`character_table.json` / `char_roles.json`：`python scripts/update_character_table.py`（直接从 GitHub 下载，无需本地仓库） |

## 资源更新流程

```bash
# 1) 同步可更新资源（levels.json / ONNX / PaddleOCR / battle_data / ocr_config / 模板 / 头像）
python scripts/update_resources.py

# 2) 若需最新 levels.json（无需本地仓库，直接从 GitHub 下载）
python scripts/update_levels.py

# 3) 若需最新干员职业表（character_table.json / char_roles.json，直接从 GitHub 下载）
python scripts/update_character_table.py

# 4) 若需最新 ONNX/OCR/模板/干员数据，先 pull Maa
git -C /Maa pull
python scripts/update_resources.py

# 5) 若需最新干员头像，先 pull ArknightsResources
git -C /ArknightsResources pull
python scripts/update_resources.py

# 6) 若需从 tasks.json 重新提取 roi.json
python scripts/update_resources.py --regen-roi

# 7) 只看会做什么，不实际复制
python scripts/update_resources.py --dry-run
```

资源根目录可通过环境变量 `AVR_RESOURCE_DIR` 覆盖，便于在非默认路径下使用。

> 也可由 GitHub Actions 自动同步（avatar / tile / data / config），详见 [GitHub Workflow 说明](./workflow说明.md)。

## 资源说明

`/workspace/resource/` 总大小约 214 MB，所有子目录均纳入版本控制（开箱即用）：

- `resource/avatar/` 约 81 MB：干员头像库（1372 个 `char_*.png` / `sp_char_*.png`），用于助战识别。
- `resource/tile/levels.json` 约 67 MB：940+ 个关卡的标准地图数据。
- `resource/onnx/` 约 40 MB：3 个战斗识别 ONNX 模型（`skill_ready_cls` / `deploy_direction_cls` / `operators_det`）。
- `resource/ocr/maa/` 约 13 MB：Maa finetune PaddleOCR det/rec 模型。
- `resource/data/` 约 15 MB：战斗/OCR 配置 + 干员职业表。
- `resource/template/` / `resource/config/`：模板图片与 ROI 配置。

其中 `avatar` / `tile` / `config` / `data` 由 GitHub Actions workflow（`.github/workflows/sync-resources.yml`）定期从上游仓库自动同步并提交；`onnx` / `ocr` / `template` 体积大且为二进制文件，已在仓库中但不通过 workflow 自动同步，由开发者本地运行 `scripts/update_resources.py` 更新后手动提交。详见 [GitHub Workflow 说明](./workflow说明.md)。

精简清单与同步逻辑见 `scripts/update_resources.py` 的 `build_sync_plan`。

## 许可证合规

- 上游 `ArknightsGameResource` 的 `levels.json` 与干员头像复制到本项目使用，需遵守上游仓库许可证条款。
- 上游 `Maa`（AGPL-3.0）的资源在使用、修改、分发时需遵守 AGPL-3.0 条款。本项目通过 `scripts/update_resources.py` 只读复制所需资源到 `resource/`，未修改上游仓库本身。
- 上游 `Kengxxiao/ArknightsGameData` 的 `character_table.json` 遵循其仓库许可证。
- 本项目自身代码遵循其 `pyproject.toml` 声明的许可证（如有），与上游资源许可证相互独立。
