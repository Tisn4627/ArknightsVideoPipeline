## 1. 安装与启动

### 1.1 环境要求

- **操作系统**：Windows 10 / 11（本开发环境）
- **Python**：3.12 或更高版本
- **ffmpeg / ffprobe**：需要在系统 PATH 中可用
- **MAA（MaaAssistantArknights）**：项目目录内需包含可识别的 MAA 目录（如 `MAA-v5.12.1-win-x64`）

### 1.2 安装依赖

推荐使用项目自带的虚拟环境：

```powershell
# 进入项目目录
cd ArknightsVideoPipeline-dev

# 创建虚拟环境（如尚未创建）
python -m venv venv

# 激活虚拟环境
.\venv\Scripts\activate

# 安装依赖（包含 PyQt6 GUI 库）
pip install -r requirements.txt
```

> 安装 PyQt6 时可能需要下载约 80MB 的 Qt 运行库，请保持网络畅通。

### 1.3 启动 GUI

```powershell
# 在虚拟环境中执行
python gui.py
```

启动成功后将弹出主窗口。如果习惯命令行，CLI 入口 `python main.py` 仍然保留且功能不变。

## 2. 主界面组成

启动后主窗口参考 Material Design 3 官网风格布局，分为几个区域：

| 区域 | 位置 | 内容 |
|------|------|------|
| Navigation Rail（导航栏） | 窗口最左侧 | Home / Settings / Info 入口，图标+标签；窗口较窄时自动折叠为仅图标 |
| Hero 区域 | Home 页内容区顶部 | 应用大标题 "Arknights Video Pipeline" |
| 配置卡片 | Home 页卡片网格左侧 | 背景板图片、合成风格、跳过步骤、操作按钮（Start / Cancel） |
| 视频文件卡片 | Home 页卡片网格右侧 | 批量视频文件列表（添加 / 排序 / 删除 / 单文件状态与进度） |

| 日志卡片 | 进度卡片下方 | 运行日志，支持自动滚动、复制、清空 |

## 3. 功能模块操作说明

### 3.1 添加视频文件

主页右侧的 **Video files** 卡片用于管理待处理的视频文件列表（取代了旧版 "Pipeline steps" 步骤状态卡片与配置卡片中的单视频输入框）。列表支持批量添加、排序、删除与单文件状态跟踪，完整说明见下方 [3.13 批量视频处理](#313-批量视频处理) 章节。

快速上手：

1. 点击卡片顶部的 **Add videos** 按钮，在弹出的文件对话框中多选视频文件；
2. 也可以直接从文件管理器**拖放**视频文件到列表区域；
3. 支持的格式：`.mp4`、`.avi`、`.mkv`、`.mov`、`.flv`、`.wmv`，重复文件会自动忽略。

> 添加视频后，可在每行使用上移 / 下移 / 删除按钮调整顺序或移除条目。处理时程序会按列表顺序依次执行。

### 3.2 选择背景板图片

1. 在左侧配置区找到 **背景板图片**；
2. 点击 **浏览** 选择背景板图片；
3. 支持的格式：`.jpg`、`.jpeg`、`.png`、`.bmp`、`.webp`。

> **注意**：只有选择 **style1** 合成风格时才必须提供背景板图片。切换到 **style2** 后，背景板图片输入框会自动禁用并清空。

### 3.3 设置 MAA 路径

1. 点击导航栏的 **Settings** 进入设置页面；
2. 在 **高级** 卡片下找到 **MAA path**；
3. 点击 **浏览** 选择 MAA 项目目录（包含 `MaaCore.dll` 的文件夹）。

> 如果留空，程序将使用 `config/pipeline.json` 中配置的 `maa_path`。若路径无效，运行时会提示错误。

### 3.4 设置输出目录

1. 在设置页面的 **高级** 卡片下找到 **Output**；
2. 点击 **浏览** 选择用于存放处理结果的文件夹。

> 若留空，默认输出到 `output/<视频名>/` 目录下。

### 3.5 选择合成风格

在 **合成风格** 下拉框中选择：

| 风格 | 说明 | 是否需要背景板 |
|------|------|----------------|
| **style1** | 底板图片 + 视频叠加，文本显示于视频区域旁 | 是 |
| **style2** | 全屏视频 + 底部居中字幕 | 否 |

### 3.6 设置日志级别

1. 在设置页面的 **高级** 卡片下找到 **Log level** 下拉框；
2. 选择日志级别：

- **DEBUG**：最详细，包含每帧匹配结果
- **INFO**：常规运行信息（推荐）
- **WARNING**：仅警告和错误
- **ERROR**：仅错误

日志会同时显示在界面下方的 **运行日志** 区域，并写入 `output/<视频名>/pipeline.log` 文件。

### 3.7 跳过步骤

如果只想执行部分步骤，可以勾选对应的复选框。复选框以 3 列网格排列，共两行：

| 复选框 | 对应步骤 |
|--------|----------|
| MAA | 视频转 MAA 作业 JSON |
| Formation | 编队配置转文本 |
| Actions | 操作指令转文本 |
| Track | 识别开始按钮时间戳 |
| Compose | 视频合成 |

> 窗口宽度较小时，该网格会自动适应，避免复选框被截断。

### 3.8 输入校验

点击 **Start** 时，程序会自动校验全部输入，检查：

- 列表中的视频文件是否存在、格式是否支持、是否能被 ffprobe 解析；
- style1 风格下背景板图片是否存在；
- MAA 路径是否存在（如果已填写）。

如果存在问题，会弹出提示框列出所有错误，不会开始处理；通过则进入批量处理流程。

### 3.9 开始处理

配置完成后，点击 **Start**：

1. 程序读取 **Video files** 列表中的全部路径，按顺序依次处理；列表为空时会弹出错误对话框提示 "请先添加至少一个视频文件"；
2. 右侧 **Processing status** 卡片显示整批总进度（如 "Processing 2/5"），每个视频在列表行内还有独立的进度条与状态文字；
3. **运行日志** 会实时输出处理信息；
4. 处理过程中列表变为只读，**Start** 按钮变为 **Cancel**。

处理过程中，界面不会卡顿，您可以继续查看日志或点击 **Cancel** 取消。详见 [3.13 批量视频处理](#313-批量视频处理)。

### 3.10 取消处理

处理过程中，点击 **Cancel** 按钮即可请求停止。由于底层 MAA 识别、OpenCV 匹配等操作无法安全强制中断，取消请求会在**当前视频文件**处理结束后生效，列表中后续未处理的文件将不再执行。

### 3.11 使用左侧导航栏

窗口最左侧是精简后的 Material Design 3 风格 Navigation Rail：

| 图标 | 标签 | 功能 |
|------|------|------|
| Home | Home | 返回主页面（默认选中） |
| Settings | Settings | 切换到设置页面（主题 + 配置文件生成 + 高级配置） |
| Info | Info | 点击显示关于对话框（不离开当前页面） |

当窗口宽度小于 960px 时，导航栏会自动折叠，只显示图标；将鼠标悬停或重新拉大窗口即可恢复图标+标签。

### 3.12 设置页面

点击导航栏的 **Settings** 进入设置页面。页面包含三张卡片：

#### 3.12.1 外观（Appearance）—— 主题切换

- 卡片右侧有一个 Material Design 3 风格的开关 **深色主题**；
- 拨动开关即可在浅色与深色主题之间切换，**效果即时生效**（实时预览）：Navigation Rail、卡片、按钮等所有控件颜色会立即同步更新，原生窗口标题栏也会跟随切换为深色或浅色（Windows 需 10 1809+，通过 DWM API 即时刷新；macOS 通过 NSAppearance 跟随；Linux 效果取决于桌面环境，KDE 通常跟随，GNOME 标题栏由 GTK 主题控制可能不跟随）；
- **主题会持久化保存**：切换后关闭窗口，主题写入独立的 `config/gui.json`（与 `pipeline.json` 完全解耦）；下次启动 GUI 时自动恢复上次的主题，无需重新切换；
- 再次进入设置页时，开关会自动反映当前主题状态。

#### 3.12.2 配置文件（Configuration files）—— 按类型生成

- 卡片列出 6 种配置文件类型，每个复选框标注名称与目标文件：

  | 选项 | 目标文件 | 说明 |
  |------|----------|------|
  | Pipeline | `pipeline.json` | 主流水线配置 |
  | Formation | `formation.json` | 编队配置 |
  | Actions | `actions.json` | 操作指令配置 |
  | Track | `track.json` | 开始按钮识别配置 |
  | Compose · style1 | `video_compose/style1.json` | style1 视频合成配置 |
  | Compose · style2 | `video_compose/style2.json` | style2 视频合成配置 |

- 勾选需要的类型（可点击 **一键选择全部** 全选、**取消全部选择** 清空）；
- 点击 **生成默认配置**，程序会按所选类型在 `config/` 目录下生成（或重置为）默认配置文件，与 CLI 中执行 `python main.py --init-config <module>` 行为一致；
- 生成结果会显示在按钮右侧的状态文本中：成功显示生成数量，失败会用红色标出失败项；未选择任何类型时提示错误。

> 提示：首次使用前建议在设置页生成全部默认配置，确保 `config/` 目录下配置文件完整。

#### 3.12.3 高级（Advanced）—— 运行时配置

- **MAA path**：选择 MAA 项目目录（包含 `MaaCore.dll` 的文件夹）；
- **Output**：选择输出目录，默认为 `output/`；
- **Log level**：选择日志级别（DEBUG / INFO / WARNING / ERROR）。

> 这三个控件在主页和设置页共享同一实例，避免双源状态不同步。修改后立即生效，无需重新启动。

点击设置页底部的 **Back to home**（或导航栏的 **Home**）即可返回主页。

### 3.13 批量视频处理

主页右侧的 **Video files** 卡片取代了旧版 "Pipeline steps" 步骤状态卡片，配合左侧配置卡片中的背景板图片、合成风格、跳过步骤等共享选项，可一次性处理多个视频文件。

#### 添加文件

两种方式向列表添加视频：

- **点击 Add videos 按钮**：弹出系统文件对话框（`QFileDialog.getOpenFileNames`），支持多选；过滤器为 `.mp4 .avi .mkv .mov .flv .wmv`；
- **拖放添加**：从文件管理器直接拖放视频文件到列表区域即可。

仅接受上述 6 种扩展名，不支持扩展名的文件会被静默忽略；已在列表中的文件会自动去重，不会重复添加。

#### 调整顺序

每个视频条目左侧显示 1 起始的序号，反映当前处理顺序。每行右侧提供 **上移 / 下移** 两个图标按钮，点击可将该文件上移或下移一位。处理时严格按列表顺序依次执行。

#### 删除文件

- **单条删除**：点击该行的 **删除（垃圾桶）** 图标按钮，移除该文件；
- **全部清空**：点击顶部的 **Clear** 按钮，移除列表中的全部条目。

#### 状态显示

每个视频条目包含独立的状态图标、进度条（140px，0–100%）和状态文字，状态包含以下四种：

| 状态 | 文字 | 含义 |
|------|------|------|
| 等待中 | `等待中` | 尚未开始处理 |
| 处理中 | `处理中` | 正在执行流水线 |
| 已完成 | `已完成` | 全部步骤成功（状态图标显示对勾） |
| 失败 | `失败` | 处理出错（状态图标显示叉号） |

#### 总体进度

主页下方的 **Processing status** 卡片显示整批总进度。进度按 `(已完成文件数 × 100 + 当前文件进度) ÷ 总文件数` 计算，并配有实时文字提示，例如：

- 开始处理第 2 个文件时显示 "Processing 2/5"；
- 完成 4 个文件时显示 "Completed 4/5"。

#### 启动与取消

- 点击 **Start** 开始按列表顺序依次处理。若列表为空，会弹出错误对话框提示 "请先添加至少一个视频文件"；
- 处理过程中列表变为只读：**Add videos** / **Clear** / 上移 / 下移 / 删除按钮全部禁用；**Start** 按钮变为 **Cancel**；
- 点击 **Cancel** 会在当前视频文件处理结束后停止，列表中后续未处理的文件不再执行。

#### 错误隔离

某个视频文件处理失败时不会中断整批：失败行的状态显示为 `失败`，程序继续处理后续文件。整批结束后，若有任意文件失败，会弹出一个汇总对话框（critical 级别）告知成功 / 失败的文件数量；全部成功的文件行状态为 `已完成`。

#### 配置持久化

用户每次添加、删除或调整视频顺序时，当前列表会立即写入 `config/pipeline.json` 的 `video_paths` 字段（路径转为绝对路径，空字符串被过滤）。下次启动 GUI 时自动恢复上次的列表与顺序。

#### 主题适配

列表中的进度条填充色、状态图标颜色、状态文字颜色均跟随当前浅色 / 深色主题设置。在设置页切换主题时，列表配色会即时刷新，无需重启。

## 4. 处理流程示例

### 示例 1：style1 完整处理

1. 在 **Video files** 卡片中点击 **Add videos**（或拖放），添加 `video.mp4`；
2. 在 **Background** 旁点击浏览，选择 `bg.png`；
3. （可选）进入设置页面设置 **MAA 路径** 与 **输出目录**；
4. 确认 **合成风格** 为 `style1`；
5. 点击 **Start**，等待处理完成；
6. 在输出目录中查看生成的 `output_video.mp4` 与报告文件。

### 示例 2：style2 无需背景板

1. 在 **Video files** 卡片中添加视频文件；
2. 将 **合成风格** 切换为 `style2`；
3. 此时 **Background** 会自动禁用；
4. 点击 **Start**。

### 示例 3：仅运行 MAA 识别

1. 在 **Video files** 卡片中添加视频文件；
2. 勾选 **Skip steps** 中的 "Formation"、"Actions"、"Track"、"Compose"；
3. 点击 **Start**；
4. 只生成 Copilot JSON 文件后结束。

## 5. 常见问题与解决办法

### Q1：启动 GUI 时提示 "No module named 'PyQt6'"

**原因**：虚拟环境中未安装 PyQt6。

**解决**：激活虚拟环境后执行：

```powershell
pip install -r requirements.txt
```

---

### Q2：点击 "Start" 后提示 "请先添加至少一个视频文件"

**原因**：**Video files** 列表为空。

**解决**：点击 **Add videos** 按钮或拖放视频文件到列表区域，添加至少一个视频文件后再点击 **Start**。若之前添加的文件已被移动或删除，请删除失效条目后重新添加。

---

### Q3：style1 提示 "需要背景板图片"

**原因**：style1 合成风格必须在视频画面上叠加背景板图片。

**解决**：
- 选择一张背景板图片；或
- 将 **合成风格** 切换为 `style2`（全屏视频 + 字幕，无需背景板）。

---

### Q4：MAA 识别步骤失败

**可能原因**：
- MAA 路径未配置或配置错误；
- 输入视频分辨率、帧率不符合 MAA 要求；
- MAA 依赖的运行库缺失。

**解决**：
1. 确认 MAA 路径指向包含 `MaaCore.dll` 的目录；
2. 查看 **运行日志** 中的具体错误信息；
3. 尝试使用 CLI 运行相同命令，对比错误输出：`python main.py video.mp4 -b bg.png`。

---

### Q5：日志区域没有输出

**原因**：日志级别设置过高，或日志尚未产生。

**解决**：将 **日志级别** 调整为 **INFO** 或 **DEBUG**，然后重新开始处理。

---

### Q6：取消按钮没有立即生效

**原因**：当前正在执行的 MAA 识别、OpenCV 模板匹配或视频合成等操作无法被安全强制中断。

**解决**：取消请求会在当前步骤边界生效。如果任务长时间无响应，可以关闭窗口强制退出，但这可能导致临时文件残留。

---

### Q7：界面显示字体异常或出现 "Cannot find font directory" 提示

**原因**：在无头服务器或某些精简 Windows 环境中，Qt 6 未能找到字体目录。

**解决**：
- 在普通 Windows 桌面环境中运行时通常不会出现此问题；
- 若仍出现，可安装常用字体（如 Microsoft YaHei、Consolas），或在项目根目录创建 `fonts/` 目录并放入 TTF 字体文件。

---

### Q8：配置没有保存

**原因**：程序仅在正常关闭窗口时保存当前配置；强制结束进程可能导致配置丢失。

**解决**：点击窗口右上角关闭按钮正常退出。流水线配置保存到 `config/pipeline.json`，GUI 主题偏好独立保存到 `config/gui.json`，下次启动自动恢复。

### Q9：深色主题下窗口标题栏仍是白色

**原因**：标题栏由操作系统绘制，需通过平台 API 单独设置。本程序在切换主题时会同步调用：
- **Windows 10 1809+ / Windows 11**：通过 DWM API（`DwmSetWindowAttribute` 设置 `DWMWA_USE_IMMERSIVE_DARK_MODE`，配合 `DWMWA_CLOAK` cloak/decloak + `DwmFlush` 强制 DWM 重建合成表面）即时刷新标题栏；
- **macOS**：通过 Qt 的 `setColorScheme` 映射到 `NSAppearance`，原生标题栏自动跟随；
- **Linux**：通过 Qt 的 `setColorScheme` 通知平台插件，标题栏是否跟随取决于窗口管理器/桌面环境（KDE 通常跟随，GNOME 标题栏由 GTK 主题控制可能不跟随）。

**解决**：
- Windows：确认系统版本为 10 1809+ 或 Windows 11；
- macOS：无需额外操作，标题栏应自动跟随；
- Linux：若标题栏未跟随，属于桌面环境限制，不影响应用内部主题切换功能；
- 旧版本 Windows（低于 1809）不支持此特性，标题栏会保持系统默认颜色。
